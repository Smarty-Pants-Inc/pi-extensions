# Pi 1.0 compatibility and upstream review

Audit snapshot: 2026-10-07. The tested development baseline is **Pi 1.0.4**, the npm `latest` release observed for `pi-coding-agent`, `pi-agent-core`, `pi-ai`, and `pi-tui`. This review covers all **29 workspace packages: 27 extensions and two libraries**. It does not update an existing installation or publish packages.

Sources: [released host changelog](https://github.com/earendil-works/pi/blob/v1.0.4/packages/coding-agent/CHANGELOG.md), [npm metadata](https://registry.npmjs.org/@earendil-works%2Fpi-coding-agent), and the installed 1.0.4 declarations, runtime, documentation, and SDK examples. The [0.99.1](pi-0.99-compatibility.md), [0.87.1](pi-0.87-compatibility.md), [0.85.1](pi-0.85-compatibility.md), and [earlier upstream](upstream-refresh.md) reviews remain historical snapshots.

## Host ownership is not a version promise

All 28 packages that consume Pi declare host modules as `peerDependencies` with the literal range `"*"`. Host-provided modules must not appear in runtime or optional dependencies. This includes the four Pi packages, canonical `typebox`, and legacy `@sinclair/typebox`; the host loader maps legacy TypeBox and its supported subpaths to its canonical implementation. Installing a second runtime copy can bypass those mappings and duplicate module identity.

The exact test versions belong in development dependencies: the four root Pi pins and existing package-local Pi pins are **1.0.4**. Canonical TypeBox is **1.3.27**, matching that host rather than independently following TypeBox's latest tag. Legacy TypeBox development dependencies remain available for source tests. `pi-subagents-protocol` has no Pi dependency.

A wildcard peer documents **module ownership**, not compatibility with every past or future Pi release. This review does not rerun the old-host matrices or replace their historical results with a new blanket claim. The package checker now rejects runtime host dependencies, non-wildcard host peers, mismatched Pi development pins, and published source imports missing a host peer. Packaged-loader smoke rejects warnings as well as errors. Extracted package roots are loaded through host settings so manifest-warning provenance survives reload; a packed negative fixture proves that a runtime host dependency reaches and fails the same warning assertion.

## Relevant host changes

- Pi **1.0.0** removes the agent-core harness APIs and `pi-agent-core/node`; ordinary Agent and loop APIs remain. None of the workspace packages imports those removed surfaces. Fullscreen TUI is now the default.
- Pi **1.0.3** renames the Azure provider to `azure`, while the API ID `azure-openai-responses` and `AZURE_OPENAI_*` environment variables remain. No workspace runtime import or hard-coded provider key needs this rename; user-managed provider configuration remains host-owned.
- Pi **1.0.4** retains MCP tools for ordinary `tools`/`--tools` allowlists unless an entry starts with `mcp__`. `tools: []` or `noTools: "all"` disables MCP as well. Restricted execution therefore needs an actual invocation policy, not an assumption that a built-in-only list denies every other route.
- MCP hyphens normalize to underscores, collisions receive suffixes, and codemode descriptions no longer enumerate all tools. Startup enumeration and prompt inspection are not permission boundaries. Planning freezes its admitted tool names and checks actual calls, including nested calls; subagent policy remains enforced through `tool_call`.
- Terminal Goal tools and planning completion are model-only: nested execution cannot safely propagate their top-level termination semantics. They stay directly declared with codemode enabled, including codemode-only mode.
- Pi **1.0.4** adds `ToolLoadout.getPromptGuidelines()`. Tool exposure, `prepareLoadout`, nested tool events, virtual models, and host dependency warnings already existed in **0.99.0**; fixes around those boundaries are not incorrectly described as newly introduced 1.0 APIs.

## Remaining boundaries

- Loader acceptance, deterministic SDK behavior, and rendered-component tests are not live OAuth, external-provider, physical-terminal, browser, GitHub, MCP-server, or external-LSP acceptance tests. Platform-specific command integrations also require their actual environment. POSIX clipboard cancellation targets the invoked utility, not arbitrary daemonized descendants; harmless subprocess fixtures do not establish physical clipboard acceptance.
- Codex Remote V2 supports unchanged description-only loadout rewrites after fresh context preparation and matching provider wire evidence. Hidden declarations, unproven transformations, changed public tool surfaces, or different remote wire tools use native fallback; cached provider callbacks cannot approve unsent registry edits. No public effective-loadout snapshot is assumed. A later compaction hook can still mutate prompt/history after this extension's final validation; the host supplies no atomic checkpoint-publication boundary.
- Child configuration preserves captured parent and child configuration-root provenance, including immutable ancestor denials across worktrees and nested calls. Denied/unknown trust suppresses project-owned settings, agent definitions, skill preloading, description templates, and project-scoped context discovery before resolution; the actual fallback declaration retains its provenance. Native global settings and MCP files are also checked before SDK parsing: aliases into any retained denied root fail child admission; genuine global files and aliases into approved parent roots retain their host-defined semantics. Raw path components and symlink targets are checked before dot-segment normalization, so an intermediate denied directory remains attributable even when the final leaf escapes outside. These admission checks are not an atomic filesystem snapshot or proof against concurrent filesystem mutation, and do not restrict arbitrary filesystem/process capabilities of deliberately trusted global code.
- Subagents retain a checked compatibility bridge to private `ModelRegistry.runtime` because the public stream helper is not a lossless full child-session constructor. Admission fails if the bridge is unavailable. Explicitly sanitized task summaries remain the supported context-transfer route; raw `inherit_context` remains fail-closed.
- Pi provides no post-veto, pre-leaf-commit lifecycle hook. Tree preflight and committed ownership fences mitigate races, but do not make cross-extension asynchronous navigation atomic. Tool permissions and explicitly opted-in inspection programs are not an OS sandbox.
- Native external-editor subprocesses retain Pi's own lifetime semantics: retiring the JSON dialog fences its draft/terminal callbacks but does not provide OS-level termination of the editor program. Quit suppression across replacement requires statusline to remain loaded: if reload removes it, no replacement instance observes subsequent quit, and the pending editor retains the host's native restart behavior.
- Gate memoization uses a Git HEAD/status/diff snapshot and disables reuse when untracked files are present. It does not establish ignored or external inputs, submodule contents, concurrent mutations, or command determinism.
- Worktree recovery verification runs independently of a retired UI owner's signal. Git calls retain per-command timeouts, not an overall recovery deadline; recovery admission and reservations are not an atomic filesystem guarantee.
- Analytics cannot identify raw provider-hook ownership after a cache-warming decision or extension reload: the host supplies neither a final warming decision nor a request/completion ID, and reload can retain an in-flight warmer whose callbacks reach fresh factories. It conservatively suppresses those hooks until a non-reload session start, so HTTP observations and failed dispatch counts can be undercounted. Successful finalized assistants and their tool/skill attribution remain counted; this is not a complete network-attempt log.
- `/usage` remains scoped to its documented default session store; adding arbitrary alternate-store discovery is optional.
- `pi-gpt-fast` transforms the request payload, not the provider's stream options. In Pi 1.0.4, a requested priority tier with a returned `service_tier: "default"` can therefore be priced at the default multiplier. Accurate accounting for that fixture requires a host bridge from the effective transformed request tier into SSE/WebSocket pricing. This non-blocking host limitation is not fixed by rewriting extension result wrappers or duplicating a pricing catalogue.
- The historical matrix remains historical. `"*"` peers must not be presented as validation of untested hosts. No package version was manually bumped, and no release or global installation update is part of this review.
